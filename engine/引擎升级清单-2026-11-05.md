## 一、真 bug（引擎侧必须改，否则扩展代码一定会踩）

### 1. 图片纹理跨设备串用 → 画成方块/乱码 ★★★★★

- **现象**：改渲染分辨率（应用窗口重启 → 新 RenderDevice）后，页面上所有 PNG 图标变成灰白方块。
- **根因**：纹理句柄属于**设备上下文**，而图片缓存键只有「路径 + 尺寸」。设备一重建，旧 `tex id` 在新设备上就是无效句柄 → 画成实心方块。
- **主引擎现状**：`999-27` **还没有图片系统**（`src/ui/win/` 下无 `ImageSystem.*`），图片逻辑目前散在 `src/ui/Background.cpp`、`src/ui/Font.cpp` 各自解码。
- **建议**：
  1. 把游戏侧 `src/ui/win/ImageSystem.{h,cpp}` 整体上游到引擎（统一解码 + 面积平均重采样 + 预乘 alpha + 缓存）。
  2. 上游时必须带上两条铁律：
     - **缓存键含设备维度**：`key = devicePtr + "|" + path + "#" + quantizedPx`
       （游戏侧实现见 `ImageSystem.cpp` 的 `load()`，`char devKey[24]; snprintf(devKey, "%p", dev);`）
     - **设备重建即清缓存**：在设备创建入口调用 `g_images.releaseAll()`
       （游戏侧在 `AppWindow::initDevice()` 开头；引擎若有多应用多设备，`releaseAll` 是全局的，会连别的设备缓存一起清 —— 更稳的做法是缓存按设备指针分区，见第 1.1 条）

### 1.1 建议：图片缓存按设备分区（多应用安全）

当前 `ImageSystem` 是全局单例 + 全局 `cache_`。多应用各持一个 `RenderDevice` 时，纹理 A 不能在设备 B 上用。
建议引擎侧直接做成 **per-device 分区**（`std::unordered_map<const RenderDevice*, Cache>`），
设备销毁时只清自己那一区，避免"新建一个应用窗口把别的应用的图标清了"。

### 2. DropdownSystem：id 重复会互相覆盖，点击无反应 ★★★★★

- **现象**：同一窗口里两个下拉共用同一个 `id` → 后声明的覆盖前一个的状态 → 点第一个完全没反应（展开的是第二个）。
- **根因**：`DropdownSystem::findOrCreate()` 只按 `(winId, id)` 查（`src/ui/win/DropdownSystem.cpp:32-40`），**不校验 id 是否重复**。
- **建议（引擎侧三选一或都做）**：
  1. `findOrCreate` 里检测「同窗口已存在同名 id」→ 开发期打日志断言（`UI_LOG_WARN` + 首次出现即提示）。
  2. `DropdownRequest` 增一个可选 `autoId`（按声明顺序自动生成 `id#0/#1/...`），让扩展者不必手写 id。
  3. 头注释写死铁律：**「同一窗口内所有下拉 id 必须唯一；id 重复 = 状态互相覆盖」**。

### 3. RegionRequest 注释与实现矛盾（逻辑像素 vs 屏幕像素） ★★★★

- **现状**（引擎 `src/ui/win/RegionSystem.h:24-30` 与游戏侧完全一致）：
  ```
  // 区域申请请求（窗口内容区内的相对坐标，逻辑像素，系统乘 scale）
  struct RegionRequest { float x = 0, y = 0; ... };
  ```
- **实现**（`RegionSystem.cpp:77`）：`r->view = Rect(Vec2(win.x + req.x, win.y + req.y), Vec2(req.w, req.h));`
  —— **没有乘 `g_uiCtx.scale`**。所以 `req.x/y/w/h` 实际是**屏幕像素**（相对窗口左上角）。
- **后果**：扩展者照注释传逻辑值 → 区域整体错位一整个缩放倍率。
- **建议**：把注释改成与实现一致（**屏幕像素，相对窗口左上角**），并在 `RegionRequest` 字段旁注明「本引擎的窗口坐标一律屏幕像素，见 §4」。

### 4. 窗口坐标单位契约分散，容易混用 ★★★★

- **现状**：`WindowInstance.x/y/w/h` 是**屏幕像素**；`WindowConfig.defaultW/defaultH` 是**逻辑像素**（运行时乘 scale）；`WindowConfig.titleBarH`、`cornerRadii` 也是逻辑像素。
- **后果**：内容布局里混用两者 → 缩放后控件不重排 / 右侧跑位（本次实战就踩了：把 `win.w` 当逻辑宽用）。
- **建议**：
  - 引擎统一注释：`WindowInstance` 的字段改名或加注释「屏幕像素」；`WindowConfig` 的尺寸类字段统一加「逻辑像素」前缀说明。
  - 提供换算助手：`g_uiCtx.toScreen(logical)` / `g_uiCtx.toLogical(screen)`，并在 `UiContext` 里补 `pageScale(h)` 单源（游戏侧已加，引擎还没有 —— 引擎里三处视图各自算 base scale，容易分叉）。

### 5. 字体图集在高分辨率下整图集重建 → 每帧数百毫秒尖峰 ★★★★

- **现象**：渲染分辨率切到 1080p 后，字体会话升到 **4096×4096** 图集，Debug 下每帧 600→3800ms 递增尖峰（Release 轻但也有）。
- **根因**：`src/ui/Font.cpp` 的图集容量策略是「装不下就整张重建」，密度随逻辑高（`fontPxFor`）线性放大 → 高分辨率直接顶到 4096²，且重建期间整图集不可用。
- **建议**：
  - 图集上限按**逻辑高自适应**（或分块图集 / 增量不整张重建）；
  - 重建时保留旧图集直到新的可用（双缓冲），避免重建帧文字消失；
  - 给 `refreshFonts(true)` 加「密度变化超过阈值才重建」的上限保护。

### 6. 窗口右上角按钮区没有对外安全区接口 ★★★

- **现象**：扩展窗口想在自己顶部放个按钮（如设置页右上「主题工作室」），不知道系统 X / 悬浮球 / 钉按钮占了哪 → 直接被 X 压住。
- **现状**：`wbtn::closeBtnRect(win)` 存在（`src/ui/win/WindowButtons.cpp:57`）但只暴露单个按钮，没有"右侧按钮区总宽"。
- **建议**：引擎补 `wbtn::rightButtonsWidth(win)` 或 `wbtn::contentSafeRect(win)`，扩展代码直接取安全区右边界，别再手算让位量。

### 7. 处理器回调注册易漏：带滑条的窗口必须注册 drag + release ★★★

- **现象**：滑条按下能取值，但**拖不动** —— 因为处理器只注册了 render/click/hover。
- **建议**：引擎在 `HandlerRegistry` 文档或 `WinHandler` 结构体注释里明确标注：
  「**含滑条/拖拽的窗口必须注册 drag + release**；`drag` 持续更新值，`release` 复位并提交延迟提交类参数」。

## 二、可直接上游的现成改进（游戏侧已实现并验证）

### 8. 下拉文字字号随控件高度走（修「下拉按钮内容字体太小」）

- 引擎现状：`src/ui/win/DropdownSystem.cpp:145-155 / 211-219` 用 `wctl::drawTextLeftAt`，字号 = 字体图集原生大小 → 40px 高的按钮里塞 14px 的字，**控件尺寸与字号脱钩**。
- 游戏侧已修：新增单源 `dropTextPx(ctrlPx)`（控件高 × 0.46，保底 11px），按钮与列表项都走 `wctl::drawTextScaled`，字号随控件与页面缩放同步。
- **建议**：直接把这套搬进引擎（游戏侧文件：`src/ui/win/DropdownSystem.cpp`）。

### 9. 关闭按钮绘制收编（矢量 X，避免 "✕" 缺字形变方块）

- 引擎现状：`src/ui/win/WindowButtons.cpp:169-181` 自己画 X（hover 红底 + 白色叉）。
- 游戏侧已收编到 `wctl::drawCloseBtn`（常态 tabText@120 圆角底 + hover 红底 + 白色矢量 X，与账号面板共用同一实现）。
- **建议**：引擎侧同样收编，避免每个窗口各画一套（历史上 "✕" 字形缺失渲染成乱码方块就是这么来的）。

### 10. 滚动条默认样式

- 游戏侧已把 `UiContext::scrollbarStyle` 默认从 `0`（细轨）改为 `2`（胶囊·无按钮），全引擎滚动条统一胶囊形。
- 引擎现状默认仍是 `0`。这是**风格决策**，两边要统一（否则「同一套 UI」在引擎与游戏里长得不一样）。

## 三、建议补进引擎文档的「铁律」清单（本次实战血泪）

1. 同一窗口内**下拉 id 必须唯一**（重复 = 状态互相覆盖，点击无反应）。
2. 滚轮容器内布局**必须用 `h.contentW` / `g_regions.getContentW()`**，不能用视口全宽 —— 否则右侧控件压到滚动条轨道上。
3. 区域申请的 `req.x/y/w/h` 是**屏幕像素**（相对窗口左上角），**系统不乘 scale**。
4. `WindowInstance.x/y/w/h` 是**屏幕像素**；`WindowConfig` 的尺寸字段是**逻辑像素**（运行时乘 scale）。
5. 纹理句柄属于设备 → **图片缓存键必须含设备维度**，**设备重建必须清缓存**。
6. 带滑条的窗口**必须注册 drag + release**（滑条拖拽靠这两个回调）。
