| 其余 28 个 | ≤50 | 多为注释/样式/局部扩展 |

**处理原则（建议）**：

1. **引擎为源、游戏为扩展**：引擎公共文件（`src/ui/win/*System.*`、`Font.*`、`UiContext.*`、`WindowButtons.*`、`RegionSystem.*`）只允许"游戏侧追加扩展"，不允许改公共逻辑；一旦改了，就是一次"待回灌"。
2. **每次改引擎公共文件，跑一次差异审计**（见下），确认游戏侧是否需要同步。
3. **游戏侧验证出的引擎级 bug，先修引擎、再同步回游戏**，避免只修一边（本次之前就出现过游戏侧修了图片系统、引擎还没有的情况）。

## 四、差异审计命令（改完引擎随手跑）

```bash
# 列出两侧同名文件的差异行数（降序），>0 的都要判断方向
cd "E:/工作区"
comm -12 <(cd 继续/万象沙盒/src && find . -name "*.cpp" -o -name "*.h" | sed 's|^\./||' | sort) \
         <(cd UI开发/999-27/src && find . -name "*.cpp" -o -name "*.h" | sed 's|^\./||' | sort) \
| while read f; do
    n=$(diff <(tr -d '\r' < "继续/万象沙盒/src/$f") <(tr -d '\r' < "UI开发/999-27/src/$f") | grep -c "^[<>]")
    [ "$n" -gt 0 ] && echo "$n $f"
  done | sort -rn
```

## 五、结论一句话

**内核同源，但已经是两份会各自演进的拷贝。** 本次引擎级缺陷两边都已修齐；以后再改公共文件，按上面的审计命令确认一遍，就不会出现"一边修了、一边还是旧的"。
